Tạo License Notices, SBOM và checksum SHA-256

Quy trình theo các lệnh đã chạy và ba script hiện có trong dự án. Thực hiện tại thư mục gốc bằng Git Bash trên Windows.

Ngày biên soạn: 08/09/2026

1. Chuẩn bị

  • Mở Git Bash tại thư mục chứa package.json và package-lock.json.
  • Cài Node.js và npm phù hợp với dự án; package.json hiện yêu cầu Node.js ≥ 20. Công cụ chạy qua npx có thể có yêu cầu Node.js riêng.
  • Đảm bảo node_modules đã được cài đặt thành công và phản ánh dependency cần lập báo cáo. Nếu lần cài trước bị gián đoạn, hoàn tất cài đặt trước khi xuất báo cáo.
  • Chuẩn bị ba script: enrich-license.cjs, enrich-sbom.cjs và enrich-sbom-sha-256.cjs.
  • Cần kết nối registry khi npx phải tải công cụ và khi lấy dữ liệu npm audit.
cd '/d/SourceCode/[PROJECT_REACTJS]/001-hds-admin'
node --version
npm --version
Các lệnh bên dưới ghi đè file báo cáo cùng tên ở thư mục gốc. Tài liệu HTML này nằm trong _tmp; không chạy các script từ trong _tmp vì chúng đọc file theo thư mục làm việc hiện tại.

Cài đặt / chạy công cụ bằng npx

Tại thư mục gốc dự án, chạy lần lượt:

npx license-checker
npx @cyclonedx/cyclonedx-npm

npx gọi công cụ để chạy ngay; nếu chưa có công cụ phù hợp, npm có thể hỏi tải package. Kiểm tra tên và phiên bản rồi nhập y. Đây là thao tác chạy công cụ, không phải lệnh thêm dependency vào package.json.

Hai lệnh trên chưa chỉ định file đầu ra. Để tạo các file phục vụ quy trình enrich, dùng các lệnh có --json và --output-file trong phần Các bước thực hiện.

Hướng dẫn sử dụng license-checker

Chạy trong thư mục dự án đã cài dependency. Các ví dụ dưới đây phục vụ các mục đích riêng; không cần chạy tất cả.

Mục đíchLệnh
Xem thông tin giấy phépnpx license-checker
Tổng hợp theo giấy phépnpx license-checker --summary

Chỉ lấy dependency productionnpx license-checker --production --json > licenses.base.json

Chọn phạm vi báo cáo trước khi xuất JSON. Nếu dùng --production, chạy lại node enrich-license.cjs để cập nhật kết quả tương ứng.

Nguồn tham khảo: Tài liệu license-checker — các tùy chọn CLI.

2. Thực hiện theo thứ tự

Bước 1 — Xuất thông tin giấy phép

npx license-checker --json > licenses.base.json

Tạo licenses.base.json, làm đầu vào cho script bổ sung nội dung giấy phép. Nếu npx hỏi cài công cụ, kiểm tra tên/phiên bản được hiển thị rồi nhập y để tiếp tục.

Bước 2 — Tạo thông báo thư viện bên thứ ba

node enrich-license.cjs

Script đọc licenses.base.json, lấy toàn bộ nội dung file giấy phép vào licenseText, lấy dòng đầu tiên có chữ “copyright” vào copyright, rồi bỏ hai trường path và licenseFile.

Kết quả: THIRD_PARTY_NOTICES.json. Terminal hiển thị Done!. Nếu không tìm thấy file giấy phép hoặc dòng copyright, trường tương ứng có thể rỗng.

Bước 3 — Tạo SBOM gốc

npx @cyclonedx/cyclonedx-npm --output-file sbom.base.json --output-format JSON --omit dev --spec-version 1.5

Xuất sbom.base.json ở định dạng JSON, chọn CycloneDX 1.5 và bỏ dependency phát triển qua --omit dev.

Trong lần chạy đã ghi nhận, npx yêu cầu cài @cyclonedx/cyclonedx-npm@6.0.1. Muốn chỉ định đúng phiên bản đó khi chạy lại, dùng npx @cyclonedx/cyclonedx-npm@6.0.1 với các tham số còn lại giữ nguyên.

Bước 4 — Xuất bản lockfile để đối chiếu Tùy chọn

node -e "require('fs').writeFileSync('lock.inspect.json', JSON.stringify(require('./package-lock.json'), null, 2))"

Tạo bản JSON được căn lề của package-lock.json để kiểm tra thủ công. Script enrich không đọc lock.inspect.json; nó đọc trực tiếp package-lock.json.

Bước 5 — Lấy báo cáo audit

npm audit --json > audit.json

Tạo audit.json để bổ sung dữ liệu lỗ hổng. Kiểm tra đây là báo cáo hợp lệ trước khi chạy bước 6; lỗi kết nối hoặc registry cũng có thể được trả về dưới dạng JSON.

Lệnh audit có thể trả mã thoát khác 0 khi phát hiện lỗ hổng, dù file báo cáo đã được tạo. Vì vậy không nối toàn bộ quy trình bằng && rồi mặc định mã thoát khác 0 luôn là lỗi xuất file.

Bước 6 — Bổ sung SBOM và tạo checksum

node enrich-sbom.cjs

Script đọc sbom.base.json, audit.json, package-lock.json; bổ sung dữ liệu integrity và audit, ghi sbom.json, sau đó tính SHA-256 của chính file này.

SBOM enriched with SHA + audit data
Created: sbom.json.sha256

Bước 7 — Tạo lại checksum riêng Tùy chọn

node enrich-sbom-sha-256.cjs

Bước 6 đã tạo sbom.json.sha256, nên không bắt buộc chạy lại. Dùng bước này nếu cần tạo lại checksum sau khi hoàn tất thay đổi có chủ đích đối với sbom.json.

Bước 8 — Xác minh checksum

sha256sum --check sbom.json.sha256

Kết quả mong đợi:

sbom.json: OK

OK nghĩa là SHA-256 của file hiện tại khớp checksum đã lưu. Nếu chỉnh sửa file sau đó, kết quả kiểm tra có thể không còn khớp.

3. Lệnh tổng hợp để chạy lại

Chạy lần lượt từng lệnh và kiểm tra kết quả trước khi sang bước kế tiếp. Khối này giữ cả hai bước tùy chọn như quy trình đã thực hiện.

npx license-checker --json > licenses.base.json
node enrich-license.cjs

npx @cyclonedx/cyclonedx-npm --output-file sbom.base.json --output-format JSON --omit dev --spec-version 1.5

# Tuy chon: ban lockfile de doi chieu
node -e "require('fs').writeFileSync('lock.inspect.json', JSON.stringify(require('./package-lock.json'), null, 2))"

npm audit --json > audit.json
node enrich-sbom.cjs

# Tuy chon: buoc enrich-sbom da tao checksum
node enrich-sbom-sha-256.cjs
sha256sum --check sbom.json.sha256

5. Kiểm tra và giới hạn của script hiện tại

Checksum không phải kiểm tra chất lượng SBOM. Kết quả sbom.json: OK không chứng minh file hợp lệ theo schema CycloneDX, không chứng minh dependency an toàn và không xác thực nguồn phát hành.

Các điểm dưới đây được rút ra từ mã script hiện tại:

  • getIntegrity(name, version) chỉ tra node_modules/${name}; tham số version chưa được dùng. Script chưa xử lý đầy đủ package có scope trong trường group hoặc dependency nằm lồng trong lockfile.
  • Script chép nguyên chuỗi integrity vào hashes[].content và gán nhãn SHA-512; chưa có bước chuyển đổi hay xác minh định dạng hash.
  • audit.vulnerabilities được gán trực tiếp vào sbom.vulnerabilities, chưa có bước chuyển đổi hay kiểm tra schema CycloneDX. Cần xác minh schema nếu hệ thống nhận yêu cầu SBOM chuẩn.
  • SBOM dùng --omit dev, còn lệnh audit và license-checker trong quy trình không chỉ định cùng bộ lọc. Không mặc định ba báo cáo có cùng phạm vi dependency.
  • Nếu audit.json không có trường vulnerabilities, script dùng object rỗng. Vì vậy phải kiểm tra audit có thành công, tránh nhầm lỗi đầu vào thành “không có lỗ hổng”.

6. Nội dung đầy đủ các script

Lưu từng đoạn vào file .cjs tương ứng tại thư mục gốc. Nội dung bên dưới được chép từ các file hiện có; giữ nguyên cả các giới hạn đã nêu ở phần kiểm tra. Đây là bản chụp tại lúc cập nhật tài liệu, không tự đồng bộ khi script thay đổi.

enrich-license.cjs

const fs = require("fs");
const path = require("path");

const licenses = JSON.parse(
fs.readFileSync("licenses.base.json", "utf8")
);

for (const [pkg, info] of Object.entries(licenses)) {
let licenseText = "";
let copyright = "";

if (info.licenseFile && fs.existsSync(info.licenseFile)) {
    licenseText = fs.readFileSync(info.licenseFile, "utf8");

    // Tìm dòng Copyright đầu tiên
    const match = licenseText.match(/^.*copyright.*$/gim);

    if (match && match.length > 0) {
    copyright = match[0].trim();
    }
}

info.copyright = copyright;
info.licenseText = licenseText;

// Không xuất đường dẫn local
delete info.path;
delete info.licenseFile;
}

fs.writeFileSync(
"THIRD_PARTY_NOTICES.json",
JSON.stringify(licenses, null, 2)
);

console.log("Done!");

enrich-sbom.cjs

const fs = require("fs");
const crypto = require('crypto');

const sbom = JSON.parse(fs.readFileSync("sbom.base.json", "utf8"));
const audit = JSON.parse(fs.readFileSync("audit.json", "utf8"));
const lock = JSON.parse(fs.readFileSync("package-lock.json", "utf8"));

function getIntegrity(name, version) {
  const dep = lock.packages?.[`node_modules/${name}`];
  if (!dep) return null;

  const integrity = dep.integrity; // sha512
  return integrity || null;
}

sbom.components = sbom.components.map((c) => {
  const integrity = getIntegrity(c.name, c.version);

  return {
    ...c,
    hashes: integrity
      ? [
          {
            alg: "SHA-512",
            content: integrity
          }
        ]
      : c.hashes
  };
});

// attach vulnerability info (ITS often wants this)
sbom.vulnerabilities = audit.vulnerabilities || {};

const file = 'sbom.json';
fs.writeFileSync(file, JSON.stringify(sbom, null, 2));

console.log("SBOM enriched with SHA + audit data");

// create file .sha256
const hash = crypto
  .createHash('sha256')
  .update(fs.readFileSync(file))
  .digest('hex');

fs.writeFileSync(`${file}.sha256`, `${hash}  ${file}\n`);

console.log('Created:', `${file}.sha256`);

enrich-sbom-sha-256.cjs

const fs = require('fs');
const crypto = require('crypto');

const file = 'sbom.json';

const hash = crypto
  .createHash('sha256')
  .update(fs.readFileSync(file))
  .digest('hex');

fs.writeFileSync(`${file}.sha256`, `${hash}  ${file}\n`);

console.log('Created:', `${file}.sha256`);
