## Workflow trigger contract

The workflow has three triggers:

- `pull_request` targeting `main`, filtered to `tools/storybook-to-markdown/**` and `.github/workflows/build-storybook-extension.yml`.
- `push` to `main`, using the same path filters.
- `workflow_dispatch` without a path filter.

All triggers run the `validate` job. The `package` job depends on successful validation and is skipped for pull requests. A main push or manual run checks out the same commit again, rebuilds and packages it, verifies the ZIP, and uploads only `release/storybook-to-markdown-v<manifest-version>.zip`. The explicit checkout/rebuild avoids dependence on files from the validation job.

## Build and packaging steps

Both jobs use Node.js 22 and do not install packages: the extension has no dependencies or lockfile and does not need the React app build. Validation runs extension JavaScript syntax checks, the mocked Chrome smoke test, build/packaging regression tests, `npm run build`, `npm run package`, and `npm run verify`.

The packaging job runs `npm run package` and `npm run verify`, confirms the expected versioned archive exists, checks it with system `unzip -t`, and asserts that `manifest.json` is an archive-root member. It uploads no `dist/`, tests, reports, or app files.

Artifact name: `storybook-to-markdown-v<manifest-version>-<commit-sha>`.

Retention: 30 days.

The ZIP is the extension distribution package. It is separate from the All Docs ZIP generated by the extension, which contains exported Storybook Markdown.

## Security and permissions

The workflow grants only `contents: read`. Pull requests use the ordinary `pull_request` event; the workflow does not use `pull_request_target`, repository secrets, write permissions, release creation, or Chrome Web Store publishing. The Actions used are pinned to immutable commit SHAs: checkout v7.0.1, setup-node v7.1.0, and upload-artifact v7.0.2.
